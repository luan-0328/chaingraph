## RAG 开发集基线

使用 [63 条人工编写问题](../evals/rag_cases.json)，其中 49 条有分块证据标签、
14 条知识库外问题。语料为仓库 7 篇规则，真实切分得到 57 块。该集是开发集，
不是独立留出集；证据标签仅表示仓库原文，不证明其中业务规则的合规性或已实现程度。

默认强制使用本地 512 维字符 n-gram 哈希向量、余弦排序、Top 4、阈值 0.05。
不访问业务数据库或模型接口。语料、问题集哈希及逐题结果见 [JSON 报告](rag-baseline.json)。

| 指标 | 结果 |
|---|---|
| Recall@4（证据标签召回） | 71.43%（35/49） |
| MRR@4（首条相关证据倒数排名均值） | 0.6429 |
| 知识库外问题拒检率 | 0%（0/14） |
| 有依据问题误拒检率 | 0%（0/49） |

当前低阈值与哈希向量会为所有未知问题返回片段，不能据此宣称能可靠识别知识缺口。
检索误命中不等于最终模型必然答错，当前报告没有评测最终答案或转人工行为。
评测使用原始问题，不包含 Agent 的检索查询改写、Qdrant 索引和发布状态过滤。
毫秒级离线查询延迟也不代表远程 Embedding 或完整 Agent 时延。

后续应固定本基线，另建留出集，显式配置真实 Embedding 做对照，在开发集校准阈值，
再评估未知问题拒检与有效问题召回的取舍。只有测量显示需要时再引入混合检索或重排。
`--provider configured` 使用环境配置，可能调用收费 Embedding；本轮没有执行。
