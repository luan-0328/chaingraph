## 保留的部署与功能边界

- Checkpoint 使用 SQLite；SSE 使用进程内总线。多机器部署需要共享 Checkpoint 与跨进程事件分发，当前不具备完整的跨机器无缝接管。
- 崩溃执行由后续请求触发超时回收；尚无独立后台任务自动扫描、恢复执行。
- 用户长期记忆的自动写入、读取和删除闭环已于 2026-10-10 补齐，见下文；没有加入模型压缩记忆。
- 支持全额退款；部分退款和完整退货、换货履约不在当前 V1 已实现范围内。

这些边界不影响当前单机演示定位，但不应在简历或部署说明中描述成已经实现的生产能力。

## 2026-10-10：补齐跨工单记忆

验证结果：新增 7 项专项回归通过；最终全量 **140 passed，187.19 秒**。使用隔离数据库和临时 Checkpoint；编译及空白检查通过。真实模型回答质量和前端交互没有在本轮重新验收。

- Agent 或人工结单时，在同一数据库事务中保存一条有工单来源的处理摘要。通过工单行锁避免并发重复写入；重复结单更新原摘要。
- 生成方案前读取当前用户最近三条有效记忆，包括跳过业务查询节点的纯咨询路径。读取失败时继续处理当前工单，记录失败状态。
- 排除当前工单；来源工单重新打开、处理中或被删除时，不再读取其旧摘要。用户之间严格隔离。
- 历史摘要只是背景，不代替当前订单查询、规则或审批；不自动推断用户偏好或信用风险。
- `GET /api/auth/me/memories` 查看最多 20 条有效记忆；`DELETE /api/auth/me/memories/{memory_id}` 删除本人记录。删除不会清理原始工单和历史 Checkpoint；如果同一工单以后重新结单，会生成新的处理摘要。
- 修复退款历史统计：先在数据库按用户筛选再统计，不再从全站最近 50 条记录中截取。

展示步骤见 [记忆演示说明](docs/memory-demo.md)。
