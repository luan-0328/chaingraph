# 跨工单记忆演示

这项能力保存的是历史处理摘要，不是长对话压缩，也不是模型自行学习用户偏好。

1. 使用用户 A 创建工单，并通过 Agent 或客服将其处理为已解决。
2. 在 Swagger `/docs` 使用用户 A 的 Bearer Token 调用 `GET /api/auth/me/memories`，可以看到 SUMMARY 记录及 `ticket:<id>` 来源。
3. 用户 A 创建另一张工单并触发 Agent。进度中会出现“正在读取该用户的历史处理摘要”；生成方案时读取最近三条有效记忆。即使新工单只咨询、未走业务查询节点，也能读取。
4. 重新打开第一张工单，再查询记忆接口：它的旧处理结论会被排除。重新解决后更新原摘要，不会不断新增。
5. 使用用户 B 查询自己的记忆，不会看到 A 的摘要；B 删除 A 的记忆返回 403。A 删除自己的记忆返回 204，后续新执行不再读到它。

无需为了展示额外调用模型总结历史：摘要由后端根据工单内容和已记录的解决方案截取生成，有来源、长度受限，可以追溯。

记忆接口已加入 Swagger；本次没有新增前端记忆管理页面。历史记忆不代表当前订单状态，退款仍必须经过 Service 的实时校验。
