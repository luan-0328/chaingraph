# 售后规则

本文件是售后业务的总则，规定售后类型、状态流转、以及与工单之间的关系。

## 一、售后类型

系统支持四种售后类型：

- 退款（REFUND）：用户要求退还订单款项，是最主要的售后类型，本版本重点实现。
- 退货（RETURN）：用户把已签收的商品寄回，商家验收后退款，即退货退款。
- 换货（EXCHANGE）：用户要求更换同款或等值商品，不涉及退款。
- 其他（OTHER）：不属于以上三类的售后诉求，例如补发配件、开票、修改地址等。

用户提交售后申请时必须明确选择类型，类型一旦确定后由客服审核时确认，不允许用户直接修改已完成单。

## 二、售后单与退款记录的区别

- 售后单（AfterSale）表达"用户想要退款或退货"这件事，是业务申请单。
- 退款记录（RefundRecord）表达"钱真的退回去了"这笔资金流水。
- 一次售后允许产生多次退款记录，失败可以重试，因此两者是分开的两张表。

## 三、售后状态流转

售后单的状态按以下路径流转：

- APPLYING：用户已提交申请，等待系统或客服处理。
- PROCESSING：处理中，已转人工审核或正在等待用户补充材料。
- APPROVED：审核通过，等待执行退款或换货。
- REJECTED：审核拒绝，必须在原因中写明拒绝依据。
- COMPLETED：售后完成，退款到账或换货商品已寄出。
- CANCELLED：用户主动撤销申请。

正常路径为 APPLYING → PROCESSING → APPROVED → COMPLETED。
被拒绝时路径为 APPLYING → PROCESSING → REJECTED，用户可以对拒绝结论提出申诉并重新提交。

## 四、售后与工单的关系

- 售后单是业务对象，工单是客服处理载体，两者不是同一件事。
- 一个售后单可以关联多个工单，例如先咨询再申请、退款失败后再次跟进。
- 工单也可以完全不关联售后单，例如纯咨询类问题。
- 用户提交售后申请时，系统自动创建关联该售后单的工单，工单携带 order_id 与 after_sale_id 作为业务上下文。
- 工单状态按 OPEN → PROCESSING → WAITING_HUMAN → RESOLVED → CLOSED 流转，解决与关闭是两个不同动作。

## 五、处理时限

- 售后申请提交后，系统必须在 24 小时内给出初审结论。
- 需要用户补充材料的，客服应在 24 小时内一次性告知所需材料清单。
- 已通过的退款应在 3 个工作日内执行完毕。
- 超时未处理的售后单应升级提醒客服主管，并在工单中标记为高优先级。

## 六、与订单状态的联动

- 用户提交售后申请后，订单的 after_sale_status 置为 APPLYING。
- 退款执行中时，订单的 after_sale_status 置为 REFUNDING。
- 退款成功后，订单的 after_sale_status 置为 REFUNDED，payment_status 置为 REFUNDED。
- 订单状态变更只能由售后服务统一控制，禁止在接口层直接改状态。

## 七、转人工的通用条件

出现以下任一情形，售后必须转人工处理：

- 订单已发货。
- 退款金额超过 500 元。
- 商品存在损坏或质量争议。
- 用户对系统或 Agent 的处理结论有异议。
- 涉及换货、退货等需要物流往来的场景。
